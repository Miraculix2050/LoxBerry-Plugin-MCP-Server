# Event-history chart preparation measurements

The chart-prepare path emits sanitized `event_history_chart_timing` entries for
the fixed phases `config_load`, `selector_refresh`, `revalidation`,
`history_prepare`, `serialization`, and `cgi_delivery`. Phase entries contain
only elapsed milliseconds. Fixed resource fields report selected source count,
discovered control count, serialized helper response bytes, and CGI response
bytes. The request correlation ID is generated by the CGI; no source IDs,
names, tokens, endpoints, or project values are included.

## Controlled target-device run

Run on the same LoxBerry test installation and under the same service load.
Avoid changing the configuration, selector cache, or recorded history during a
run. Use one, two, three, and four already-visible chart sources, repeating
each case at least five times.

For each source count:

1. Make one cold request after restarting only the test plugin service. Record
   each fixed timing phase and the resource fields from the LoxBerry plugin log.
2. Make five warm requests in sequence without restarting the service or
   changing configuration. Record the same fields for every request.
3. Repeat the set once while the usual competing workload is present and once
   with that workload idle, if both conditions can be scheduled consistently.
4. Report median and range per phase; retain the per-request samples so the
   effect of the cold first request remains visible. Do not combine helper and
   CGI timings: they are separate phases.

The chart page issues `event_history_chart_prepare` as the first request after
sources are selected. In browser developer tools, the action can be replayed
through the page itself by selecting the same source count and reopening the
chart view. Use the resulting log entries with their request IDs; do not copy
request payloads into notes. Compare the measured `selector_refresh` phase to
the previous 6–8 s baseline, and report cold/warm and idle/loaded results
separately. This repository environment has no configured LoxBerry target, so
these device measurements remain to be collected there.
